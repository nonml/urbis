# VGA-084.1 "No overlap": brief for the next agent

Written 2026-09-29 by Claude so that any model, a small one included, can finish this
slice without making design calls. Every number below was run against the real code:
applying all four steps on a scratch copy takes the checker from 57 to 0.

Read `AGENTS.md` first, at least **The six laws** and **How to work**. After that,
this file is all you need.

## Where it stands

- **The checker is built and in the gate.** `npm run check:overlap` runs
  `scripts/check_overlap.mjs`, which builds the real towers headless and lists every
  pair of buildings, or building and zoning lot, whose footprints intersect. Each one is
  named by its table row, e.g. `INFILL_TOWERS[3]`.
- **Today it finds 57 pairs. Done means 0.** VGA-084 says 48. That count used tower
  shafts; the checker uses the 4.2 m ground-floor podium, which is what you see from
  the street. At shaft size the checker reproduces 48 exactly.
- **The ratchet.** `MAX_OVERLAPS` in the checker equals the count on `main`. The
  checker fails if the count goes up, and also if it goes down, so every fix has to
  lock in its gain. After each step, set it to the new count. **Never raise it.**
- **Before shots:** `docs/shots/slice-053-before-street.png` and
  `slice-053-before-city.png`. The black slabs in the city shot are the silhouettes.

## The loop, once per step

1. Make the edit the step gives. It is only that edit; do not tidy anything nearby.
2. `npm run check:overlap`. The count must equal the step's target. If it does not,
   stop and re-read the step.
3. Set `MAX_OVERLAPS` in `scripts/check_overlap.mjs` to that count.
4. `npm run gate`. Every check must be green. Write down the `draws:` lines.
5. Screenshot: `npm run build`, then
   `node scripts/shot.mjs docs/shots/slice-053-stepN '[{"name":"street"},{"name":"city","keys":["z"],"wait":3000}]'`.
   Open both PNGs and compare them with the before shots. Nothing should be missing
   that the step did not remove.
6. Commit, one commit per step:

   ```
   fix(block): <what the step did>

   Why: <one line from the step's "why">
   Overlap: <before> → <after> pairs.
   Draws: <measured delta, from the gate or shot.mjs, not from this file>
   ```

   Evidence goes in `docs/shots/`. Never push; the operator pushes.

## The four steps, in this order

All edits are in `src/render/block.js`.

### Step 1: narrow the south row (57 → 52)

`SOUTH_TOWERS` rows are `[x, width, height]`. Change **only the widths**:

```js
[-2, 11, 30], [10, 10, 42], [22, 11, 26], [34, 10, 36], [46, 11, 28],
```

**Why:** the centres are 12 m apart and each podium is `width + 1.2`, so two neighbours
must satisfy `w_a + w_b ≤ 21.5`. Row 0 must also stay clear of `LOTS[7]`, whose edge is
at x = -8.5. Keep x and height as they are.

### Step 2: delete the silhouettes (52 → 40)

Near the end of `buildTowers()`, delete the `silhouettes` array, the `silMat` line, the
`group.add(...silhouettes...)` line and the `footprints.push(...silhouettes...)` line.

**Why:** these are seven unlit, flat-black boxes 48–74 m tall, and five of them stand
inside the district. They are the black slabs in city view, the exact toy read VGA-084
is about, and the skyline `RING` already draws the horizon. Expect about −1 draw, and
report the number you actually measure.

### Step 3: move five skyline rows out (40 → 34)

In `buildSkyline()`, in the `RING` table:

- North rim, rows 5, 6 and 7: set z to **124** (they were 112, 118 and 110).
- West pair, rows 11 and 12: set x to **-76** and **-78** (they were -62 and -64).

```js
[-20, 124, 24, 66, 18], [20, 124, 20, 84, 16], [60, 124, 26, 56, 20],
...
[-76, 60, 18, 54, 16], [-78, -60, 20, 68, 18],
```

**Why:** the north rim stood on the terminus towers and the west pair stood on the
west avenue's row. Look at the city shot: if a moved ring tower now sits in the river
or on a mountain, say so in the commit. Do not go hunting for a better spot.

### Step 4: delete the mid-block infill (34 → 0)

Delete the `INFILL_TOWERS` table, the comment above it, and its `forEach` loop in
`buildTowers()`.

**Why:** the infill rows sit between the backs of two facing avenue rows. That strip
is 1–2 m wide, and where both rows leave a gap it is at most ~6.8 m long, while a
podium alone is over 11 m. No infill tower fits anywhere between the avenues, so there
is no real gap to fit them into. Two things change on screen, and both are expected:

- The dark voids the infill was added to fill come back in city view. Sub-slice 2
  (continuous street walls) is what fills them properly.
- The terminus towers are numbered after the infill, so their facade and shop choices
  shift.

Then set `MAX_OVERLAPS = 0`. The checker is now the plain "fails if any two footprints
intersect" test that VGA-084 asks for.

## Do not

- **Touch the setback formula** `ax + side * (8.5 + d / 2)`. VGA-084 names it, but it
  causes none of the 57 pairs. Changing it moves the noodle bar door
  (`RAMEN_FRAME x = -6.4`, `src/sim/interior.js`), the roof stairs and the sign offsets.
  It belongs to sub-slice 2.
- **Move a `LOTS` entry** (`src/sim/zoning.js`). The zoning tests are built on them.
- **Raise `MAX_OVERLAPS`, or change the checker so it passes.**
- **Chase these page errors.** They were there before this slice:
  `[arc] sign lot_arden / lot_trust does not fit the atlas`, and one 404.
- **Act on the finding below.**

If the gate fails for a reason the step does not explain, retry twice, then revert
the step and report it (AGENTS.md).
